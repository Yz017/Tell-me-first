# tell-me-first：流程入口

用通俗易懂的中文沟通，先说明用户能看到的变化，再按需解释技术细节。本文件负责衔接步骤，具体操作必须读取对应步骤文件 后执行。

## 步骤与加载

以下链接相对于本文件所在目录解析。开始任务时先读取第一步；恢复任务时根据对话中的完成情况和明确授权，读取当前应执行的步骤。

| 步骤 | 必须读取的步骤文件 | 进入条件 |
| --- | --- | --- |
| 1. 对齐需求 | [develop-step-1-align](references/develop-step-1-align.md) | 开始任务，或需求需要重新对齐 |
| 2. 明确目标并取得开发同意 | [develop-step-2-scope](references/develop-step-2-scope.md) | 第一步完成，用户明确同意进入第二步 |
| 3. 获准开发并总结 | [develop-step-3-implement](references/develop-step-3-implement.md) | 用户同意第二步的具体方案及范围 |
| 4. 获准测试并报告 | [develop-step-4-test](references/develop-step-4-test.md) | 第三步完成，且用户已同意具体测试安排 |

## 衔接规则

- 每步完成后按该步骤要求请求下一步的授权，并等待回复。未回复不代表同意；不要一次执行后续所有步骤。
- 用户明确同意后，自动读取下一步的 `SKILL.md`，再执行该步骤，不要求用户手动调用下一步。不要仅凭步骤名称或记忆执行。
- 用户已经针对具体方案、范围或测试作出的明确授权继续有效，不重复询问。例如第二步方案已展示后，用户说“按这个方案改完并测试”，可同时授权第三步与已说明的测试；仍需依次读取各步骤文件。
- 用户提出调整时留在对应步骤更新内容；改变已确认目标或范围时回到第二步，需求变化时回到第一步。
- 上下文恢复后，结合对话确认当前步骤和授权，不将“已读 Skill”当作“已获授权”。不要额外创建流程状态文件。
- 若下一步文件缺失或无法读取，告知具体路径并暂停该步骤，不跳过加载。
- 用户最新的明确指示优先；本流程不授权提交、推送、部署或对外发送消息。
