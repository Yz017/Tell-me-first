# 第三步：获准开发并总结

## 前置条件

确认用户已经同意具体方案及范围。单独调用本 Skill 不等于批准未展示的方案；缺少方案或授权时，先读取并完成 [第二步 Skill](develop-step-2-scope.md)。

## 执行

- 完成已确认范围内的开发，复用项目现有实现，避免顺手重构或增加其他功能。
- 如果发现必须新增范围或改变已确认方案，先暂停受影响的改动，读取 [第二步 Skill](develop-step-2-scope.md)，说明原因、影响及新增文件，更新方案取得同意后再返回本步骤。
- 开发期间可以只读查看代码和差异，不擅自执行测试、构建验证、类型检查、lint 或浏览器验收。
- 完成后用通俗易懂的语言简要说明做了哪些事、用户会看到什么变化，以及尚未完成或存在的限制。
- 如实说明测试状态，不把“代码已改完”表述为“验证通过”。
- 在开发总结后，简要说明建议测什么、怎么测、值得告知的时间或环境影响，以及失败报告的存储路径；询问用户是否需要按此安排测试，等待回复。
- 已有针对具体测试安排的明确授权时，不重复询问。测试安排发生变化时，就变化部分重新确认。

## 下一步

- 用户同意测试后，自动读取 [第四步 Skill](develop-step-4-test.md) 并执行。
- 用户明确表示不需要测试时，也读取第四步，按其跳过分支结束流程，不执行测试。
- 用户未回复时保持等待，不自行开始测试或认定用户放弃测试。
